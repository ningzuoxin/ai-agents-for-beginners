# 个人总结

## 1. AI Agent 是什么？

AI Agent 是给 LLM 装上工具和知识，使 LLM 能真正的干活，而不是仅仅回复 prompt。感知 - 决策 - 行动（运行环境，传感器，执行器），短期记忆，长期记忆。

## 2. 什么时候使用 AI Agent？

1. 开放性问题，需要 LLM 自主决策，找出解决问题的路径。
2. 多步流程，需要多轮调用工具，而非一次查询或生成。
3. 持续进化，需要根据用户反馈和环境信号持续改进。

# 第 1 章学习笔记：AI Agent 入门与用例（Introduction to AI Agents and Agent Use Cases）

> 本章目标：建立"什么是 agent、它与裸 LLM 的本质区别、什么时候该用/不该用"的判断框架。
> 核心一句话：**Agent = 给 LLM 接上工具和记忆，用"感知→决策→行动"循环把"生成文本"变成"对世界做事"；它的价值来自应对路径的不确定性，任务越确定越不该上 agent。**

---

## 1. Agent 是什么：LLM 是零件，Agent 是系统

教程定义：让 LLM 真正"做事"的系统——给它工具和知识去影响世界，而不只是回复 prompt。拆成五个要素：

- **系统**：不是单个模型，是一组协作部件。最小三件套——**环境**（在哪干活）、**传感器**（怎么读环境状态）、**执行器**（怎么行动）。
- **LLM**：大脑，负责理解自然语言、推理上下文、把模糊需求翻译成可执行的计划。
- **执行动作**：裸 LLM 只输出文本；进入 agent 系统后，文本才会变成真正执行的步骤。
- **工具**：能干什么取决于开发者接了什么线——**权限边界是设计出来的，不是模型自带的**。
- **记忆**：短期（当前对话）+ 长期（数据库、历史交互）。

> 拓展："环境-传感器-执行器"不是为 LLM 发明的，来自经典 AI（Russell & Norvig《AIMA》），agent 概念比 LLM 早几十年。LLM 革命换掉的只是"决策模块"——过去手写规则、训小模型，现在换成通用的自然语言推理引擎。**LLM 是零件，agent 是系统**，别混为一谈。

> 拓展：把五要素串起来的是一个**循环**——感知 → LLM 决策（输出"调哪个工具 + 参数"）→ 代码执行工具 → 结果回喂 LLM → 下一轮，直到任务完成。这就是 agentic loop（ReAct 式"推理-行动"循环），第 3 章的设计模式都长在它上面。

---

## 2. 七种 agent 类型：其实是两个正交维度

教程列了七类，别当名单死记，关键看出它们落在两个独立维度上。

**维度一：智能程度**（从傻到聪明）

| 类型 | 核心机制 |
|---|---|
| Simple Reflex | 硬编码规则，无记忆、无规划 |
| Model-Based Reflex | 维护并更新内部世界模型 |
| Goal-Based | 有目标，逐步推路径 |
| Utility-Based | 权衡取舍，找的是最优解 |
| Learning | 从反馈中变好 |

**维度二：组织形式**——**Hierarchical**（上层拆任务、下层执行）、**Multi-Agent Systems**（多 agent 协作或竞争）。

> 拓展：前五类是"更聪明"，后两类是"更多 agent 的组织方式"，两者正交。今天的 LLM Agent 基本都是 **Goal-Based + Learning 的混合体**（天生会拆目标、也会从对话反馈调整），所以真正的设计决策恰恰在后两类：单 agent 还是分层？要不要多 agent？——这正是第 8、14 章的主题。

---

## 3. 什么时候用 agent（以及教程没明说的"别用"）

**三个该用信号**：开放性问题（解决路径无法预先编程）、多步流程（跨多轮调用工具）、持续改进（从用户反馈或环境信号变聪明）。

> 拓展：**反面清单同样重要**——路径确定的流程（表单校验、固定 ETL、状态机客服）用普通代码更好（确定、免费、可审计）；一次调用能解决的（翻译、摘要、简单分类）裸 LLM 就够，套 agent 只增加延迟和 token；错误代价极高又要求可解释的场景，LLM 的非确定性是负债。**一句话：agent 的价值 = 应对"路径不确定性"，任务越确定越不需要 agent。**

---

## 4. 三层生态：Development → Patterns → Frameworks

- **Agent Development（开发平台）**：定义 agent *能做什么*。课程用 **Foundry Agent Service**——多厂商模型（OpenAI/Mistral/Llama）、授权数据、标准化 **OpenAPI 3.0** 工具定义。
- **Agentic Patterns（模式）**：可复用的 prompt 编排策略。多步任务里手写每一步 prompt 不可行，这就是模式存在的理由（第 3 章展开）。
- **Agentic Frameworks（框架）**：现成模板/基础设施，解决三件事——接工具、**可观测可调试**、多 agent 协作。课程主线框架是 **Microsoft Agent Framework (MAF)**。

> 拓展：三层类比 Web 开发——平台≈云服务，模式≈设计模式（不绑定语言），框架≈Spring/Django（把模式工程化）。**模式是框架的地基**：只学框架 API 只会调、不会设计。这也是课程"先模式、后框架"编排的原因。

---

## 5. 踩坑 & 易错点

- **把 LLM 当 agent**：没有工具、没有循环，它只是个聊天框。
- **把七种类型当选择题**：现代 LLM agent 是混合体；真正要选的是组织形式。
- **"能用 agent" ≠ "该用 agent"**：确定性任务上，agent 只带来成本、延迟、不可复现。
- **忽视权限边界**：工具给多了就是攻击面，"能搜航班不能改记录"要在设计期定死。
- **跳过模式直接学框架**：框架 API 换代快，模式寿命长得多。

---

## 6. 选型心法

- 单步、路径确定 → 裸 LLM 调用（最便宜最快）。
- 开放问题、单角色可覆盖 → 单 agent + 工具。
- 要拆角色 / 并行 / 各有专精 → 分层或多 agent（第 8 章的拆分决策）。
- 原型期用轻框架，要生产级可观测与托管 → Foundry + MAF（第 2、16 章）。
