# 第 5 章学习笔记：Agentic RAG（智能体检索增强生成）

> 本章目标：搞懂 RAG 从"固定管线"到"自主决策循环"的进化。
> 核心一句话：**Agentic RAG = 把"何时检索、怎么检索、检索够不够"的决策权从人转移给模型；循环就是第 4 章的工具调用原语反复跑——"LLM → 工具 → LLM → …"，记忆防死循环，能力边界 = 你给的工具和数据源。**

---

## 1. 核心认知：RAG 的决策权转移

这一章最核心的认知：**Agentic RAG 不是"RAG + agent"的简单叠加，而是检索决策权从人转移给模型。**

| | 传统 RAG | Agentic RAG |
|---|---|---|
| 流程 | 检索一次 → 塞 prompt → 生成（固定管线） | 迭代循环：检索 → 评估 → 改写/换工具 → 再检索 |
| 路径由谁定 | 人预编排（prompt 链 / 硬编码管线） | **模型自己拥有推理过程**（own the reasoning process） |
| 失败处理 | 照样生成（垃圾进垃圾出） | 改写查询、换检索方式，直到满意 |
| 循环形态 | 一轮 | maker-checker 式多轮 |

- **Maker-Checker（生成-校验）**：模型生成初稿后自己当自己的 checker——评估检索结果、发现缺口、补全，直到信息充分才回答。
- 收益：提高正确性、兜住畸形查询（如 NL2SQL 失败自动改写）、复杂问题多源交叉验证。

> 拓展：**为什么这个循环成立**——第 4 章的 function calling 是底座：每次"评估后调工具"就是一轮工具调用（两次 LLM 调用夹一次检索执行）。Agentic RAG 没引入任何新原语，只是把"要不要再检索、换什么工具"这个决策也交给了模型。教程原话点破：一个相对简单的循环就能产出复杂且扎根的结果，**不需要过度复杂的编排框架**。

---

## 2. 循环三要素：迭代 + 工具 + 记忆

- **迭代**：初始调用 → 工具调用 → 评估细化 → 循环直到满足。
- **工具**：检索手段多样——向量搜索（Azure AI Search）、SQL、自定义 API、Bing Web Grounding，模型按需选择和组合。
- **记忆与状态**（最容易被忽视的一环）：跨步骤记住之前试过什么、结果如何——**没有记忆的迭代 = 重复失败 = 死循环**。

---

## 3. 自纠错：失败模式的三层处理

检索无果或拿到不相关文档时，不返回低价值结果，而是：

1. **迭代重查**：改写查询（同义词/相关词）、换数据集、换策略。
2. **诊断工具**：调用辅助函数 debug 自己的推理步骤、确认检索数据正确性（tracing 可观测性）。
3. **人工兜底**：反复失败或高风险场景上报人；人的反馈还能被吸收进后续推理。

代码对应：Demo 3 检索失败时用同义词重试（hiking → mountain/nature/outdoor），**上限 3 次**——自主性要配预算。

---

## 4. 自主性的边界（Agentic ≠ AGI）

1. **域内自主**：只在已知领域内达成用户目标，手段是查询改写和工具选择。
2. **基础设施依赖**：能力上限 = 开发者给的工具和数据源，不能自己发明工具。
3. **尊重护栏**：伦理、合规、业务规则始终约束。

呼应第 4 章：**工具集决定能力边界——agent 永远调不出你没给的东西。**

---

## 5. 价值场景与治理（一句话版）

- **何时用 Agentic RAG**：① 正确性优先（合规/法规/法律——反复验证到可靠）；② 复杂结构化查询（NL2SQL 失败自主改写）；③ 长时工作流（新信息出现持续纳入、策略随势调整）。
- **治理三件**：可解释推理（审计轨迹：查了什么/看了哪些源/怎么推理的）、偏差控制（检索策略调优 + 定期审计输出）、人工监督（高风险决策不替代人而增强人）。

---

## 6. 踩坑 & 易错点

- **理解成"多调几次检索"**：本质是决策权转移（模型决定检索策略），不是循环次数；没有自主决策的多轮检索只是硬编码管线多跑几遍。
- **无记忆的迭代**：不记录上次尝试和结果，就会陷入重复失败循环。
- **"先检索再回答"是软约束**：instructions 里写 "ALWAYS search first" 只是 prompt 级约束，模型仍可能靠参数知识跳过检索直接回答——grounding 需要验证手段（呼应第 4 章"prompt 是软约束，架构才是硬约束"）。
- **没有重试上限**："直到满意"没有预算上限会烧钱烧轮次，实践要像代码里那样明确"最多 N 次"。
- **工具描述含糊**：老问题升级——模型决定"何时检索、检索什么"的唯一依据仍是工具 description 和参数说明（Annotated 参数说明同理）。
- **拿自主性当通用能力**：Agentic RAG 跳不出工具/数据边界，别当通用问题解决器用。
